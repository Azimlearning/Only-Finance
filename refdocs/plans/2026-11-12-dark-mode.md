# Dark mode plan (2026-11-12)

Status: plan only, nothing built. Scope: P1/P2 UI work, no finance-engine or AI-guard changes. Light stays the default (poster screenshots, print). Needs an ADR in `DECISIONS.md` when built: it reverses the "light theme only" line and the "Rejected: Dark Mode (OLED)" note in `design-system/MASTER.md` (we ship a deep-neutral dark, not OLED black/gold/purple).

## 0. Approach in one paragraph

Semantic CSS variables defined once for light (`:root`) and once for dark (`:root[data-theme="dark"]`), exposed to Tailwind through `@theme inline` so components use `bg-surface`, `text-fg`, `border-line`. The migration is a mechanical class swap (section 3), not a `dark:` sprinkle. Light values equal today's hex values, so light output is pixel-identical. Charts and SVG read the same variables (`var(--chart-1)`), so Recharts/SVG switch with no re-render logic.

Tailwind 4 confirmed via context7 (docs `dark-mode.mdx`): `@custom-variant dark (&:where([data-theme=dark], [data-theme=dark] *));` overrides the `dark:` variant for attribute-driven themes. We keep that one line as an escape hatch for the odd one-off (`dark:shadow-none`), but tokens do the work. Decision: use `data-theme` on `<html>` (not `.dark`) because it carries three states cleanly and `color-scheme` can key off it.

## 2. Mechanism

### 2.1 Files to add
- `app/src/ui/theme.ts`: `type ThemePref = 'light'|'dark'|'system'`; `getPref()`, `setPref()`, `resolve(pref)`; storage key `of_theme`, every localStorage access in try/catch; `useTheme()` hook via `useSyncExternalStore` over a tiny module store; subscribes to `matchMedia('(prefers-color-scheme: dark)')` change only while pref is `system`; `apply()` sets `document.documentElement.dataset.theme = resolved` plus `dataset.themePref`.
- `app/src/ui/ThemeToggle.tsx`: the control (section 5).
- Icons `sun`, `moon`, `monitor` added to `app/src/ui/Icon.tsx` (stroke icons, `currentColor`).

### 2.2 No-flash inline script (`app/index.html`, in `<head>`, before the stylesheet/module)
```html
<script>
  (function () {
    var p = 'light';                       // default is LIGHT, not system
    try { p = localStorage.getItem('of_theme') || 'light'; } catch (e) {}
    var d = p === 'dark' || (p === 'system' && matchMedia('(prefers-color-scheme: dark)').matches);
    var r = document.documentElement;
    r.dataset.theme = d ? 'dark' : 'light';
    r.dataset.themePref = p;
    r.dataset.themeBoot = '1';             // suppresses transitions until first paint (see 2.5)
    var m = document.querySelector('meta[name="theme-color"]');
    if (m) m.content = d ? '#0f141a' : '#0f766e';
  })();
</script>
```
Notes: default pref is `light` when nothing is stored (poster/print safety). If the CSP/test env lacks `matchMedia`, the try guards it. Also add `<meta name="color-scheme" content="light dark">` so the first paint background of the canvas is right.

### 2.3 CSS (`app/src/index.css`)
- Add after `@import "tailwindcss";`:
  `@custom-variant dark (&:where([data-theme=dark], [data-theme=dark] *));`
- Define raw vars under `:root { ... light ... }` and `:root[data-theme="dark"] { color-scheme: dark; ... dark ... }`.
- Map to utilities: `@theme inline { --color-page: var(--bg); --color-surface: var(--surface); --color-fg: var(--fg); ... }` (`inline` is required so utilities reference the live var, not a build-time constant).
- Keep the existing `@theme` overrides of `--color-teal-600/700`, `--color-gain`, `--color-loss` while migrating (so unmigrated stragglers still look right in light), then delete once section 3 is complete. Rename `--color-loss` to `--color-cost` (grep for `text-loss`/`bg-loss` first).
- Replace hex literals in the file: `body{background/color}`, `.surface*`, `.label` (`#475569`), `.field` bg + focus ring, `input[type=range] accent-color`, `::selection` (dark: `#134e4a` bg), `::placeholder` (`--fg-subtle`), `.tour-hole` (`#14b8a6` ring: keep, 6.6:1 on dark scrim), `.field:focus-within` ring uses `--focus` + `color-mix(in srgb, var(--focus) 15%, transparent)`.
- `--shadow-*` get a dark override block (table above).

### 2.4 Tailwind arbitrary values that hardcode colour
Shadows like `shadow-[0_0_0_1px_#0f766e,...]` (ScenarioSelect, Sidebar, ScenariosTab, Tour) become `shadow-[0_0_0_1px_var(--focus),0_0_0_4px_color-mix(in_srgb,var(--focus)_15%,transparent)]` or, better, one `.ring-focus-field` / `.is-selected` utility class in `@layer components`.

### 2.5 Transition and reduced motion
- Theme switch transition lives in CSS, not JS: 
  `html:not([data-theme-boot]) *, html:not([data-theme-boot]) *::before, ... { transition: background-color 160ms var(--ease-out), border-color 160ms var(--ease-out), color 160ms var(--ease-out), fill 160ms, stroke 160ms; }` is expensive on every element, so instead scope it to a short-lived `html[data-theme-anim]` attribute that `setPref()` adds for 200 ms then removes. Net: zero cost at rest, no animation on first load (boot attr removed after first rAF, and `data-theme-anim` is never set on boot).
- `@media (prefers-reduced-motion: reduce) { html[data-theme-anim] * { transition: none !important; } }` — instant swap.
- Do not animate box-shadow on theme switch (jank); background/color/border only. Existing per-element transitions (`button { transition-property ...}`) already cover colour, so only non-button surfaces need the temporary rule.
- Remove `data-theme-boot` in `main.tsx` after first `requestAnimationFrame` (or never, if the `data-theme-anim` approach is used and boot only gates it).

### 2.6 Print / screenshots
Add `@media print { :root[data-theme="dark"] { /* re-declare the light token block */ } }`. Cleaner: define light tokens in a mixin-like selector list `:root, :root[data-theme="dark"] @media print`. Plan: put the light block under `:root` and, inside `@media print`, repeat `:root[data-theme="dark"]{ ...light values; color-scheme: light }`. Poster screenshots must still be taken with pref = Light (documented in section 6).

## 4. Charts and SVG

### 4.1 Recharts
Recharts passes `stroke`/`fill` straight into SVG attributes, and SVG presentation attributes accept `var(--x)`. So `CHART` in `kit.tsx` becomes CSS-variable strings and needs no re-render on theme change:
```ts
export const CHART = {
  teal: 'var(--chart-1)', amber: 'var(--chart-cost)', blue: 'var(--chart-3)', violet: 'var(--chart-4)',
  slate: 'var(--chart-neutral)', ppp: 'var(--chart-ppp)', ink: 'var(--fg)',
  grid: 'var(--chart-grid)', axis: 'var(--chart-axis)', zero: 'var(--chart-zero)',
  tick: { fontSize: 13, fill: 'var(--fg-muted)' }, tickStrong: { fontSize: 13, fill: 'var(--fg-2)' },
  axisLabel: { fill: 'var(--fg-muted)', fontSize: 13 },
  ref: { stroke: 'var(--chart-ref)', strokeDasharray: '4 4' },
  refLabel: { fill: 'var(--fg-muted)', fontSize: 12, fontWeight: 500 },
  tooltip: { contentStyle: { background: 'var(--surface-overlay)', border: 'none', borderRadius: 8,
    boxShadow: 'var(--shadow-overlay)', padding: '10px 12px', fontSize: 13, color: 'var(--fg)' },
    labelStyle: { color: 'var(--fg)', fontWeight: 600, marginBottom: 4 },
    itemStyle: { color: 'var(--fg-2)', padding: 0 }, cursor: { fill: 'var(--chart-cursor)' } },
  legend: { fontSize: 13, color: 'var(--fg-2)', paddingTop: 8 },
}
```
Caveats to verify at build: (a) Recharts legend icon colours come from the series `stroke`/`fill` (fine with vars); (b) Recharts `<Cell fill>` and `<Bar fill>` accept vars; (c) the `fill` in `tick` objects renders as an attribute on `<text>`: fine; (d) the `.recharts-text` selector already exists in CSS; (e) `color` inside `legend` is applied through inline style (vars ok).

## 5. Theme toggle UX

- **Placement**: Header, right cluster, immediately left of the tutor/tour buttons and after the mode/tone controls; on narrow widths it stays visible (icon only, 36-40px target; the header already wraps). Not in the sidebar (sidebar is inputs).
- **Control**: a 3-option segmented control reusing `SEG_WRAP`/`segBtn` (consistent with tone/mode toggles): `Light | Dark | System`. Each segment is an icon (`sun`, `moon`, `monitor` from `Icon.tsx`, stroke style, `currentColor`) with a visible label at `lg+` and `sr-only` label below that. No emoji.
- **ARIA/keyboard**: `role="radiogroup" aria-label="Colour theme"`; each segment `role="radio" aria-checked`, roving tabindex, ArrowLeft/Right moves and selects, Home/End, Space/Enter select. Tooltip via existing `Term`-style hint is unnecessary; use `title`. When pref is System, announce resolved theme in a polite live region ("Theme: System, currently dark") only on change.
- **Behaviour**: click -> `setPref()` writes `of_theme` (try/catch), updates `data-theme` and `data-theme-pref`, `<meta name="theme-color">`, triggers the 200 ms `data-theme-anim` window (2.5). While System, listen to the media query and re-resolve live.
- **Default**: Light when nothing stored (explicit product decision for poster/print); the control shows `Light` selected on first visit. Do not auto-switch based on OS unless the user picks System.
- **Tour**: add no tour step; the welcome screen unchanged.
- **Focus ring** in dark: `--focus` `#5eead4` (11.4:1) so keyboard focus is visible on all surfaces; input glow uses `color-mix` 15%-> 25% in dark.
